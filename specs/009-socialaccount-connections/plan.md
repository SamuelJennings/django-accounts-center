# Implementation Plan: Social Account Connections Templates

**Branch**: `009-socialaccount-connections` | **Date**: 2026-05-21 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/009-socialaccount-connections/spec.md`

## Summary

Correct three existing template overrides in `dac/addons/allauth/templates/socialaccount/`
so that the social account connections flow renders inside the DAC management layout.
The core defect mirrors spec 006: `socialaccount/base_manage.html` extends
`allauth/layouts/manage.html` instead of `dac/base.html`, meaning the "Account
Connections" page has never rendered inside the Account Center sidebar/breadcrumb/card-stack
shell. `connections.html` compounds the problem by using `{% block content %}` and
allauth `{% element %}` tags throughout. `authentication_error.html` also retains
`{% element %}` tags requiring correction.

**Three template changes** (in dependency order):

1. `socialaccount/base_manage.html` — change one `extends` line to `dac/base.html` (unblocks `connections.html`)
2. `socialaccount/connections.html` — full rewrite: `{% block page.content %}`, `<c-list-group>` per connected account with inline remove form and provider badge; conditional empty-state message; "Add a Third-Party Account" section (FR-003/FR-004/FR-005)
3. `socialaccount/authentication_error.html` — corrections only: drop redundant `{% element h1 %}` (handled by entrance layout title slot), replace `{% element p %}` with `<c-text>`

Integration tests and Playwright screenshot tests are **written as part of this
feature** in `tests/test_addons/test_allauth/test_social_connections_view.py` and
`screenshots/test_social_connections_screenshots.py`.
