# Implementation Plan: Allauth Email Management Templates

**Branch**: `006-allauth-email-management` | **Date**: 2026-05-12 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/006-allauth-email-management/spec.md`

## Summary

Correct four existing template overrides in `dac/addons/allauth/templates/account/`
so that the email management flow renders inside the DAC management layout. The core
defect is that `account/base_manage.html` extends `allauth/layouts/manage.html`
instead of `dac/base.html`, meaning no email management page has ever rendered inside
the Account Center sidebar/breadcrumb/card-stack shell. One additional template
(`email_change.html`) uses `{% block content %}` instead of `{% block page.content %}`,
compounding the layout escape.

**Four template changes** (in dependency order):

1. `account/base_manage.html` — change one `extends` line to `dac/base.html` (unblocks all other templates)
2. `account/email_change.html` — full rewrite to clean Cotton structure with `{% block page.content %}` and `<c-form.card>`
3. `account/verified_email_required.html` — switch to `{% block page.content %}` with an explicit `<c-card>` wrapper
4. `account/email.html` — functional-errors-only audit; correct any broken form actions or button `name` attributes

Integration tests and Playwright screenshot tests are **pre-written** in
`tests/test_addons/test_allauth/test_email_management_view.py` and
`screenshots/test_email_management_screenshots.py`. The implementation goal is to
make those tests pass.

## Phase 1: Design & Contracts

### Template Block Contract (data-model.md)

The four templates all consume blocks exposed by `dac/base.html`:

| Block | Purpose | Default |
|---|---|---|
| `title` | Toolbar page title | (empty) |
| `page.breadcrumbs` | Breadcrumb items appended after "Account Center" root | (root only) |
| `page.content` | Main content area inside `card.stack` | "Coming soon…" |
| `extra_js` | Additional JavaScript blocks | (empty) |

### Component Interface (contracts/component-interface.md)

**`base_manage.html`** — change from:

```django
{% extends "allauth/layouts/manage.html" %}
```

to:

```django
{% extends "dac/base.html" %}
```

**`email_change.html`** — rewritten structure:

```
{% extends "account/base_manage_email.html" %}
  {% block title %} "Email Address" {% endblock %}
  {% block page.breadcrumbs %}
    {{ block.super }}
    <c-breadcrumbs.item text="Email Address" />
  {% endblock %}
  {% block page.content %}
    [warn_no_email snippet if no emailaddresses]
    <c-form.card method="post" action=account_email :form-obj="form">
      [disabled current email input if current_emailaddress]
      [disabled pending email input + resend/cancel buttons if new_emailaddress]
      [crispy email field]
      <c-slot name="actions">
        <c-button name="action_add" type="submit" variant="primary" text="Change Email" />
      </c-slot>
    </c-form.card>
    [hidden #pending-email form if new_emailaddress]
  {% endblock %}
```

**`verified_email_required.html`** — rewritten structure:

```
{% extends "account/base_manage.html" %}
  {% block title %} "Verify Your Email Address" {% endblock %}
  {% block page.content %}
    <c-card>
      <p>… verification required explanation …</p>
      <p>… link to account_email …</p>
    </c-card>
  {% endblock %}
```

**`email.html`** — audit only; correct any of:

- Per-address form `action` not targeting `{% url "account_email" %}`
- Button `name` attributes deviating from `action_primary`, `action_send`, `action_remove`, `action_add`
- Content outside `{% block page.content %}`
